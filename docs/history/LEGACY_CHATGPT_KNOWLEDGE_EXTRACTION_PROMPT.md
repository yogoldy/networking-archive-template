# Legacy ChatGPT knowledge-extraction prompt

Historical setup prompt, moved here on 2026-09-18. The initial legacy migration
is complete. This is neither a current task nor an instruction to reimport or
copy the handoff. See the [source index](../SOURCE_INDEX.md#S-002%20%E2%80%94%20Legacy%20ChatGPT%20knowledge%20handoff).

Copy and paste the prompt below into the original legacy ChatGPT project. Ask
it to use the complete project context available to it: project instructions,
past conversations, uploaded files, saved memories, prior drafts, and prior
decisions.

---

I am migrating this legacy ChatGPT project into my current Codex project,
**Networking**.

The current project home and durable file archive are:

`/Users/leogoldberg/Documents/School folders/Networking`

Your job is to create a complete, evidence-grounded knowledge handoff for a
new agent. Use the actual history and materials available inside this legacy
project. Do not rely on generic assumptions about me, networking, recruiting,
or job searching. Do not invent missing details.

Separate every important statement into one of these categories:

- **CONFIRMED** — directly supported by a message, file, instruction, or
  explicit user statement.
- **INFERRED** — a reasonable conclusion, clearly labeled as an inference.
- **UNKNOWN** — not established by the available project context.

If sources conflict, preserve the conflict and explain which source appears
newer or more authoritative. If a detail may be stale, mark it as stale or
date-bound.

## 1. Project identity and purpose

Explain:

- What this project is actually for.
- What “Networking (p-takeover)” means.
- The user's larger career, recruiting, networking, or professional goals.
- The people, firms, industries, roles, schools, programs, and communities
  that matter.
- What success would look like.

## 2. Durable user context

Extract only facts the agent should retain across future sessions, including:

- Background, education, work/internship history, and relevant experience.
- Career interests and role preferences.
- Geographic, timing, eligibility, or practical constraints.
- Strengths, concerns, recurring challenges, and decision criteria.
- Important relationships and how they should be handled.
- Terminology, shorthand, or project-specific names.

Do not include passwords, authentication codes, private tokens, or unnecessary
sensitive personal information.

## 3. What has already been done

Give a chronological or project-grouped account of completed work:

- Conversations, introductions, informational interviews, applications, and
  follow-ups.
- Research performed.
- Resumes, cover letters, personal statements, interview prep, or other drafts
  created.
- LinkedIn or other outreach already sent.
- Responses, outcomes, decisions, and lessons learned.
- Spreadsheets, trackers, templates, and systems created or used.

For each item, distinguish completed actions from suggestions that were never
executed.

## 4. Exact stopping point

State precisely:

- What was being worked on most recently.
- The last meaningful decision or user request.
- What remained unfinished.
- The next intended action.
- Any blocker, dependency, deadline, or required user decision.

If you cannot determine this, say UNKNOWN rather than guessing.

## 5. Email-writing preferences

Recover the user's actual preferences from explicit instructions and examples.
Describe:

- Tone, warmth, directness, formality, and sentence style.
- Preferred length and structure.
- Subject-line conventions.
- How to open, personalize, make the ask, and close.
- How much context to include.
- Whether to use bullets, links, scheduling language, or multiple variants.
- Words, phrases, and habits to avoid.
- How aggressively to edit versus preserve the user's voice.
- How the user evaluates whether an email “sounds like me.”

Include at least three representative examples or identify the exact source
conversation/file for each example. Label preferences as CONFIRMED,
INFERRED, or UNKNOWN.

## 6. Outreach methods and playbook

Document the actual methods used or intended, separating proven practice from
ideas:

- Email, LinkedIn, phone, events, warm introductions, alumni networks,
  communities, or other channels.
- How targets are selected and researched.
- First-touch format and personalization rules.
- Follow-up cadence, number of attempts, and stop rules.
- Tracking method and status vocabulary.
- What has worked, what has not worked, and why.
- Privacy, consent, professionalism, and reputation constraints.

Identify any canonical networking tracker or spreadsheet and explain its
important columns, status values, formulas, and workflow. Do not declare a
spreadsheet current unless the evidence supports that conclusion.

## 7. Source and artifact inventory

List every important source available in the legacy project:

- Conversation titles or dates.
- Uploaded files and attachments.
- Existing prompts or instructions.
- Resume, cover-letter, email, outreach, and interview-prep examples.
- Spreadsheets, trackers, templates, screenshots, recordings, or links.

For each source, explain what it proves, whether it may be stale, and whether
the new agent should reference it, copy it, or leave it in place.

Also identify likely related materials in the current Networking file archive,
whose root is:

`/Users/leogoldberg/Documents/School folders/Networking`

Do not claim to have inspected files you cannot actually see.

## 8. Skills, tools, and operating rules

Identify any custom instructions, skills, tools, connectors, templates, or
workflows that were actually used in this project. For each, explain:

- When it should be used.
- What inputs it expects.
- What output it should produce.
- What it must not do.
- Whether it is still relevant in Codex.

Do not list generic capabilities as project-specific skills.

## 9. Contradictions and unresolved questions

List:

- Conflicting instructions or memories.
- Stale or superseded files.
- Unknown preferences.
- Unverified contacts, dates, outcomes, or claims.
- Decisions the new agent must ask the user to make before acting.

## 10. Codex-ready handoff

End with the following exact sections:

### PROJECT_MEMORY

Write concise durable context for a future agent. Include only facts and
operating rules that should persist.

### EMAIL_STYLE

Write the recovered drafting rules and link each rule to its evidence source.

### OUTREACH_PLAYBOOK

Write the recovered outreach process, status model, cadence, and stop rules.

### SOURCE_INDEX_NOTES

List which legacy conversations/files should be compared against the current
Networking archive first.

### NEXT_ACTIONS

Give the smallest safe sequence to finish the migration. Do not send messages,
contact people, alter external records, or expose sensitive information.

### CONFIDENCE

Rate the handoff HIGH, MEDIUM, or LOW and explain exactly why.

Finally, provide a compact list titled **Questions for Leo** containing only
questions that cannot be answered from the legacy project itself.

---

Return the handoff in Markdown. Be comprehensive, but prefer precise evidence
over a polished story. The goal is to preserve the project's real knowledge,
not to recreate a generic networking assistant.
