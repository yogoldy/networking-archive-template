# Networking

Leo's career evidence and Markdown mini-CRM. This folder is also the Obsidian
vault: one set of files, usable by humans and agents, with no separate database.
Agents begin with [AGENTS.md](AGENTS.md); current status lives in
[Project state](docs/PROJECT_STATE.md), not in this home page.

## Daily use

| File | What it contributes / when to use it |
| --- | --- |
| [Home — README.md](README.md) | Navigation and the file-purpose map you are reading. |
| [Leo to-do list](docs/LEO_TODO.md) | Small, actionable personal queue; no implied deadlines. |
| [Outreach register](outreach/OUTREACH_REGISTER.md) | Lean contact index: click a name for conversation history, preparation context, and explicit next steps. |
| [Outreach scan update](docs/OUTREACH_SCAN_UPDATE.md) | Replaceable snapshot of the latest completed Mail scan, including an explicit no-new-correspondence result when applicable. |
| [Project state](docs/PROJECT_STATE.md) | Fast operational handoff: current focus, where to resume, operating state, and boundaries. |
| [Open questions](docs/OPEN_QUESTIONS.md) | Short queue of genuinely actionable unresolved facts/choices. |

In Obsidian, bookmark this page and the outreach register. Follow ordinary
Markdown links to a person, then their linked experience evidence. Add actual
conversation notes under dated headings in that person's note. Draft preparation
is not a conversation with the recipient. Keep register and person Snapshot
status aligned; explicit actions live once in Leo To-Do and link both ways.

There is no mandatory career-story formula. A request such as “use the
allocation-model accomplishment to frame this introduction” should lead to
selecting the relevant evidence, then writing for the recipient and purpose.
Do not inflate evidence or understate established ownership. Unknowns stay
visible without forcing every qualification into every email.
